## 三次任务的交付边界

1. 账号与基础安全：邮箱验证码后建号、密码登录、找回/修改密码、邮箱换绑、昵称、登录设备与退出、持久化数据、免费邮件配额与防刷；完成构建、关键接口和桌面/移动浏览器验收。
2. 收藏、留言和管理：稳定商品 ID 收藏、已售/下架保留，斗草详情文字留言与审核、会员/留言后台、外部实名核验记录、角色权限和审计、举报申诉；完成端到端联动。
3. 联调与发布准备：真实 Resend 账户/域名/QQ/163 投递、管理员双重验证、全量权限与备份恢复、依赖安全更新和回归、当前正式主线合并准备、生产配置与上线验收。对仍需用户提供的服务商配置提前列出，不能把测试邮件当作真实邮件成功。

每个阶段完成后报备实际实现、测试结果、代码状态、未完成项和下一阶段目标。阶段一和二保留为独立开发，不自动提交、推送或修改生产服务。最终发布操作按用户明确授权执行。

## 运行配置

需要 Node >=22.16 的 node:sqlite 在线备份支持，推荐受维护的 Node 24 LTS。Better Auth 固定 1.7.7，邮箱验证码由库生成并原子消费，数据库只存带密钥的摘要；密码使用库的 scrypt；会员数据与库存/百科源库/统计库分开。

参考 .env.members.example。必须配置 32 字符以上随机 MEMBERS_AUTH_SECRET、准确站点 MEMBERS_AUTH_URL、绝对 MEMBERS_DB_PATH。生产数据库拒绝放在代码发布目录内，建议 /var/lib/yandoubuy-members/members.sqlite；不得覆盖已有数据库。首次请求执行库的非破坏性迁移，后续发布要先备份并检查迁移兼容性。

缺少配置时账号操作返回明确不可用，公共页面照常可读。MEMBERS_EMAIL_MODE=disabled 不发送邮件；resend 模式需要 MEMBERS_RESEND_API_KEY、已验证域名对应的 MEMBERS_EMAIL_FROM，以及控制台确认 Free 方案，付费超额关闭。

test 模式只允许本地开发、loopback 站点和绝对测试收件目录；生产拒绝启用。测试验证码只写到隔离目录，文件权限 0600，不写日志、不提供 HTTP 读取接口、不返给用户。测试文件绝不能进入交付压缩包或 Git。

## 配额与代理

数据库内原子预留 100 封/UTC 日、3000 封/UTC 自然月；注册日额度最多95，保留5封给恢复和换绑。所有实际发送尝试都计数，异常请求保守计数，不自动退款式减回额度；没有收费供应商备选。上线前核对供应商重置周期与同账户其他发送，独立服务账户优先。

每收件邮箱至少60秒间隔、滚动24小时最多5封。来源限流只有当 MEMBERS_TRUST_PROXY=true 且反向代理确实覆写 x-real-ip 后才按客户端区分；默认不信任用户伪造的代理头，采用保守共享限流。启用代理配置时必须测试 Nginx 与应用访问边界。

请求需 JSON、同源 Origin、有大小上限；公开接口按白名单开放，不暴露原生 OTP 登录/不验证邮箱的注册路径。浏览器 JSON 不返回 bearer 会话凭证，登录设备只返回设备 ID，撤销时在服务器查找本人 token。高权限成员管理与双重验证按阶段二、三接入。

邮件回调在每请求独立的 AsyncLocalStorage 中记录错误，并在公开接口返回前抛出；避免认证库默认吞掉回调异常后仍提示成功。供应商失败、额度用尽均返回明确失败，不把任何验证码、密钥或供应商响应正文写入日志。

## 第二阶段实现（2026-10-06）

密码规则按用户要求调整为至少 6 个字符、最多 128 个字符，注册、修改、找回和管理员重置统一；原有较长密码继续可用。

收藏支持海外和国产烟斗详情，服务器解析稳定商品 ID 与展示快照，每人最多 500 条。已售正常保留，下架时显示历史快照、取消失效链接，收藏仅本人可见。

已批准的斗草百科原型整合至 public/tobacco-encyclopedia，原型源目录保持不变。可见 2130 条斗草，使用原始 blendv3 UID；data/members-blend-index.json 保存服务器允许的 UID、标题、链接与明确的旧 ID 别名，歧义别名拒绝。会员数据库不写入百科源库。新留言保存斗草名称，条目归档后历史留言仍可查看、审核。

邮箱验证会员可提交 3～2000 字的纯文字留言；默认待审，外部核验记录为 verified 且审核通过才公开。会员可撤回自己的留言、举报公开留言、申诉自己的拒绝/隐藏留言。重复提交、每日量与频率受限。公开接口仅返回昵称、文字与时间，不返回邮箱和用户 ID。撤销核验或封禁会隐藏已公开留言，恢复后仍需重新审核。

管理入口 /admin/members：会员搜索/分页，封禁与恢复、禁言与解除、修改密码、删除并匿名化账号、外部核验渠道/结果；留言审核、隐藏/拒绝/删除；举报申诉处理与管理日志。核验记录仅保存渠道、状态与操作人/时间，不收集证件照片和号码。

权限：moderator 仅处理留言及举报申诉；site_admin 管理普通会员与留言、查看审计；owner 还可分配 moderator/site_admin。普通管理员不能操作管理员账号；禁止在线新增 owner，禁止删除/降级自己或 owner。首次 owner 仅由 tools/members-owner.mjs 私有命令从已验证邮箱的现有账号提升，不存在公开提升接口。该工具首次设置后拒绝再创建其他 owner。

写管理操作前必须重新验证密码，授权绑定当前会话、有效 5 分钟；每次写入重新检查当前角色、会话及授权。角色变更、封禁、重置密码会撤销目标会话；本人改密或找回清除旧管理授权。第三阶段接入管理员双重验证后再做发布验收。

账号删除匿名化昵称和邮箱，清除凭据、会话、收藏、留言正文与相关验证码；保留不含密码的操作审计。留言删除/撤回清除正文，不复用成公开内容。所有写接口同源、限流、请求体限制；操作原因进入审计。

数据表：member_favorites、member_comments、member_reports、member_admin_grants、member_audit；member_profiles 新增 comment_muted。初始化采用非破坏性建表/加列，可重复执行；会员、百科、库存、统计数据库各自独立。

接口：/api/community 的 favorites、comments、my-comments、comments/delete、reports、appeals；/api/member-admin 的 me、members、comments、reports、audit、reauth。读接口分页每页 20 条，返回列表数量；后台页面与接口独立检查权限。

本地测试、截图和报备见聊天 outputs。真实邮件、管理员双重验证、依赖公告处理、恢复演练、同步正式主线与发布验收留第三阶段。本阶段不自动提交、推送或部署。

## 第三阶段实现（2026-10-08，发布准备）

承接同一工作区，未重做账号、收藏或留言。2026-10-09 按站主要求，正式后台仅需当前账号密码解锁，授权有效期仍为 5 分钟。验证器代码保留，默认冻结：MEMBERS_ADMIN_MFA_ENABLED=false；只有明确设置为 true 才启用下述验证器流程。后台页面根据服务端策略显示密码或密码加验证器，列表读取和管理写入均在服务端验证会话、角色和授权。普通会员仍按原有邮箱密码登录。

密码解锁继续保留来源及账号限流，并在验证密码后原子检查当前密码摘要、有效会话和管理角色，签发当前会话绑定的短期授权，记录无密码的审计日志。验证器关闭时，设置、确认、恢复码更换接口均不可用；以后重新启用验证器时，旧密码单因素授权即刻不能通过管理权限检查。截图泄露的未完成绑定已在正式库中作废，不保留或复用该种子。

站长会员卡显示账号保护说明和资料、密码设置入口，隐藏不能操作的禁用管理表单；其他会员仍显示原有下拉操作。服务端保护站长、当前管理员自身及管理权限不低于操作者的账号，界面调整不改变这些权限规则。

2026-10-09 继续整合既有浏览统计：/admin/members 增加浏览统计栏目，/admin/analytics 及旧统计登录页转到 /admin/members?section=analytics。/api/member-admin/analytics 仅允许已有有效管理授权的站长和网站管理员读取聚合数据，留言管理员和普通会员无权限。读取现有 ANALYTICS_DB_PATH 统计库，无迁移、复制、清零或认证密钥轮换，保留累计与历史访客标识。登录管理人员浏览公开页面不再计入访问，匿名和普通会员继续按原有统计规则记录。验证码、访客标识、原始访问行或私有配置不进入统计接口响应。

验证器使用 Better Auth 已用的 @better-auth/utils 0.4.2 HOTP 算法（6 位、SHA1、30 秒），以 RFC4226 向量校验；种子为 160 位随机值，使用认证密钥派生的 AES-256-GCM 加密并绑定会员 ID。首次设置需密码、当前会话及验证码，10 分钟过期。验证码允许相邻一个时间段偏差，已用时间步通过数据库事务拒绝重放，包括并发和不同会话。建议服务器启用正常时钟同步。

启用时只展示一次 8 个恢复码；每个 80 位随机值，数据库只保存带密钥摘要，使用需同时验证密码。恢复码原子消费并撤销该管理员的其他管理授权。已解锁管理员可再次输入密码更换恢复码，旧码全部作废。普通账号找回密码不移除管理员验证器；丢失验证器时用恢复码，二者均丢失须站主通过私有运维核验与备份恢复处理，无公开跳过双重验证入口。旧密码单因素授权因新增 factor_verified=0 默认值失效。删除账号清除种子和恢复码；角色、封禁、改密等原有会话撤销规则继续生效。

数据库初始化非破坏性增加 member_admin_factors、member_admin_recovery 及授权证明列。首次生产发布需先用受保护的 SQLite 在线备份保存升级前数据库，再迁移；升级后可用下述工具备份。备份工具检查完整第三阶段表结构，因此不能拿它直接验证缺少新表的旧库。生产数据库迁移、站主设置、定时备份和恢复替换尚未执行。

依赖：Next.js 与 eslint-config-next 更新为 16.4.0，更新受现有版本范围允许的传递依赖。生产依赖审计 0 项；全量审计仍有 5 项 high，源于开发期 ESLint 的 fast-glob → micromatch → braces 同一条链。核验注册表时 braces 最新仍为 3.0.3，未提供满足公告的修复版。未使用 audit fix --force 推荐的 Next 14 ESLint 降级、未忽略审计或伪造安全结论。生产安装不包含 devDependencies；开发工具问题须持续复核。

### 加密备份和恢复

先在私有环境设置独立随机 MEMBERS_BACKUP_KEY（至少 32 字符），不能复用 Resend 密钥或 MEMBERS_AUTH_SECRET。保留认证密钥用于恢复验证器；两种密钥均与备份分开保管，丢失任何必需密钥会影响恢复。

工具命令（在项目目录运行，不把密钥放在命令行）：

```text
node tools/members-backup.mjs backup <现有数据库绝对路径> <全新备份文件绝对路径>
node tools/members-backup.mjs restore <加密备份绝对路径> <全新恢复数据库绝对路径>
```

备份通过 node:sqlite 在线 API 获取 WAL 一致快照，并流式 AES-256-GCM 加密、scrypt 派生密钥，不随意复制正在运行的 SQLite 主文件。临时快照权限 0600，操作后仅清理本工具新建的临时文件；Windows 需另用 NTFS ACL 限制整个存储目录，chmod 不替代 ACL。临时快照所在磁盘建议启用加密。备份不能位于代码目录，现有目标永不覆盖。

恢复先在私有临时文件完成鉴权解密、integrity_check、foreign_key_check 和表结构检查；完整验证后才能生成全新目标。恢复撤销所有会话、管理授权及未使用验证码，保留账号凭据、收藏、留言、审计、验证器和恢复码摘要。损坏文件、错密钥或现有目标均失败，不替换当前数据库。生产恢复须先停服务并另存当前库，再核对恢复内容、路径、权限和认证密钥，获授权后切换服务配置；回滚代码不能删除会员库。每日备份调度、异机存储和实际生产恢复为部署阶段运维事项，未自动设置。

验证命令：node --test tests/members-policy.test.mjs tests/members-community.test.mjs tests/members-security.test.mjs；npm run build；npm audit --omit=dev。实际本地接口、浏览器和恢复演练证据存于第三阶段聊天 outputs，临时测试材料在 work，均不包含密钥或验证码。提交、推送和部署仍需用户明确授权。
